# Test sweep report: independent review of the characterization suite

Reviewed commit: `d5c6cba6ef99874795f16d9042eff2e2975375de` (branch `claude/dreamy-ramanujan-l3ozd4`). Sandbox: Linux, Node v22.22.0, ffmpeg and ffprobe present, so no suite was skipped for lack of them. The branch moved to `b823466` while this sweep ran (`a33335f` fixes the ScanLogger `elapsed` flake and isolates ServerBoot from a built client). Those commits change only `ScannerOrchestration.test.js`, `ServerBoot.test.js`, one snapshot entry, the manifest and docs; none of the findings other than F13 is affected, and F13 is already fixed there.

Baseline before any mutation: `npm run audit:characterization` passed (1286 passing, 7 pending, 35 test files, 937 `it()` blocks, 2485 snapshot entries, all compared; 202 of 202 route handlers hit with a success response).

Nothing tracked was changed. Mutations ran in a throwaway `git worktree` that has been removed; `UPDATE_SNAPSHOTS` and `oracle.js --update` were never run.

## 1. Verdict

Not yet. The suite is strong where it reads real behaviour (controllers, OIDC, rate limit, socket auth, scanner) and 26 of 39 mutations were caught. But 12 mutations in code the docs describe as covered survived the whole suite, and they cluster in the places a TypeScript conversion is most likely to disturb: the API-key and bearer-token branches of `TokenManager.jwtAuthCheck`, the tag-based access check in `User`, the payloads that scanner code and controllers broadcast over the socket, and every response header except `Content-Type` in the controller suites. A conversion that broke any of those would pass. Fix first: F1 to F4 (add the missing cases, widen `api.request` to keep the headers that matter, record socket payloads). Then F5 and F6 so a skipped or edited suite cannot pass CI unnoticed. None of the problems needs a redesign; each is a handful of added cases.
