- The differences are of five kinds. (a) A destructured require is split into two statements: `const { x } = require("m")` becomes `const m = require("m"); const { x } = m` (14 of the 20 files have fewer destructured require lines than before; this is what TypeScript emits for `import m = require("m")`). (b) `require("axios")` becomes `const axiosModule = require("axios"); const axios = axiosModule.default` in four files (NotificationManager, MusicBrainz, GoogleBooks, FantLab). In the installed axios 0.27.2, `require("axios").default === require("axios")` is true (checked in the audit clone), so the object is the same; with another axios major version this has to be checked again. (d) opmlGenerator.js: `module.exports.generate = ...` becomes `const generate = ...; module.exports = { generate }`. parseEbookMetadata.js: two `module.exports.x = x` lines become one `module.exports = parseEbookMetadata` object. (e) AudioFileScanner.js no longer contains `const LibraryItem = require("../models/LibraryItem")`; the original used it only in JSDoc types, so TypeScript drops it. The agent says it compared the load order of Server.js from both builds (363 modules, same order); this was not re-run, but the API smoke test (section 7) starts the server and runs a library scan with the new build.
