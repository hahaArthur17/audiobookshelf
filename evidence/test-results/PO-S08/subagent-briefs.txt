## How rule 5 is read in this run: strictly
The user reads rule 5 strictly, and wave 1 was integrated that way (one compiling controller was restored because of it). Decide by this test, and if in doubt the answer is "not allowed":
- **A cast is allowed only** (a) where the type it corrects is defined by an untyped JavaScript or vendored module (LibraryItem.js, Database.js, managers/*.js, scanner/*.js, utils/*.js, libs/*), or (b) under Allowances 1, 2 and 3 of the controllers section. - **A cast is not allowed** where it corrects a type defined by a converted `.ts` file or by a typed npm package (sequelize, express). Examples that were rejected or blocked in wave 1: a Sequelize association mixin that the converted model does not declare (`apiKey.getUser()`, `collection.getCollectionBooks()`), a too-vague return type of a converted model method, Sequelize's own typings (`where: null`, a nested `include` given as an object, `changed()?.length`).
