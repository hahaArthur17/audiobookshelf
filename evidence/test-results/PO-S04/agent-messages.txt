## Did the pattern work as written?

The overload line itself works exactly as written: it removes TS2417 with no cast, including for `hasMany`, `belongsTo`, `create`, `destroy` and `upsert`. Three things around it had to change:

1. **The JSDoc placement in CLAUDE.md is reversed.** I built `Setting` with the JSDoc above the overloads first, and the compiled file lost the 4-line `init` comment. The overloads must go above the JSDoc so the comment stays on the implementation. The PO-S02 notes have it the right way round.
2. **The real signature must be repeated as a second overload.** Read literally (one uncallable overload directly above the method), the implementation signature is hidden and a TypeScript caller gets `TS2684: The 'this' context of type 'typeof X' is not assignable to method's 'this' of type 'never'`. The build hides this today because `Database.js` is unchecked JavaScript.
3. **The constructor parameters must be optional**, which CLAUDE.md does not mention. I used `constructor(values?: CreationAttributes<X>, options?: BuildOptions)`. With required parameters, `this.findAll()` fails with `TS2684 … Type 'typeof X' is not assignable to type 'new () => X'`.

Points 2 and 3 come from scratch probes outside the repo, not from the build. The import shape used in all three is:
